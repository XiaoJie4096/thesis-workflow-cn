# Proposal Writing Rules

## General Style

Write in formal, concise Chinese academic prose suitable for an undergraduate thesis proposal. Do not expose internal reasoning unless the user asks for analysis. Avoid "下面从..." style prefaces when the user wants final text.

Prefer direct section output:

```text
一、选题依据

……

二、研究意义

……
```

When a school template uses specific headings, follow that template exactly.

## Source Integrity

Literature-related claims must come from one of these sources:

- the user's provided literature review;
- user-provided abstracts, bibliographic records, or notes;
- general, clearly non-specific background knowledge.

Do not fabricate specific author-year claims, paper titles, journals, statistics, policy dates, platform cases, or research results. If the user asks for 国内外研究现状 without supplying literature materials, include a short note such as:

```text
说明：当前未提供具体文献综述或题录摘要，以下内容仅作为研究现状的概括性初稿，后续应结合真实文献进一步补充代表性成果。
```

Keep this note brief and then provide a usable general draft.

## Section Requirements

### 选题依据

Explain why the topic is worth studying from current development trends, realistic needs, technology/application background, and the specific problem the paper addresses. Connect background to the thesis title directly. Do not rely on inflated claims.

For system-design topics, include:

- the practical problem or user need;
- why an information system, platform, application, or design solution is appropriate;
- why the topic fits undergraduate development and research conditions.

### 研究意义

Write practical and modest theoretical value. For undergraduate proposals, practical value is usually stronger than theoretical contribution.

Include:

- value for the target users or application scenario;
- value for improving a process, system, service, management method, or learning/use experience;
- limited theoretical or methodological value, such as enriching a specific application case or providing a design reference.

Avoid claiming major academic breakthroughs.

### 国内外研究现状

If a literature review is provided, summarize it by themes rather than listing papers one by one. Use phrasing such as "已有研究主要集中在……", "相关研究大致形成了……", and "现有研究仍存在……".

A strong research-status section should include:

- broad development context;
- main research directions;
- representative findings only when supplied by the user;
- limitations or gaps that lead naturally to this thesis.

When summarizing from a provided literature review, do not add new references not present in the provided material.

### 研究内容

Write a coherent description of what the thesis will actually do. For undergraduate feasibility, divide the work into manageable tasks.

For system/software topics, prefer:

- requirement analysis;
- overall architecture or functional module design;
- database/data structure or key process design when relevant;
- main function implementation;
- testing, optimization, and evaluation.

For non-system topics, prefer:

- research object and problem definition;
- literature and background analysis;
- current situation or case analysis if data is available;
- problem diagnosis;
- improvement strategy or application proposal.

Avoid assigning tasks that require inaccessible datasets, large samples, complex statistical modeling, or advanced algorithm training unless the user explicitly provides the necessary conditions.

### 研究方法

Choose methods that match undergraduate work:

- 文献研究法;
- 案例分析法;
- 问卷调查法 or 访谈法 only when the user can realistically collect data;
- 需求分析法;
- 系统分析与设计法;
- 功能测试法;
- 对比分析法.

Do not add methods merely for decoration. Each method should correspond to a real section of the thesis.

### 研究进度安排

Use a realistic undergraduate schedule. Include stages such as literature collection, proposal writing, outline refinement, draft writing, system/design work if relevant, revision, finalization, and defense preparation.

### 预期成果

State expected deliverables modestly:

- complete thesis proposal;
- complete thesis text;
- system prototype or design scheme if relevant;
- requirement/design/testing documents if relevant;
- practical suggestions or application reference.
