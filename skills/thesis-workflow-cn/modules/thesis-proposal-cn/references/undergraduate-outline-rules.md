# Undergraduate Outline Rules

## Core Rule

Only generate undergraduate-feasible outlines. Do not include an ordinary or advanced mode. The outline must support a paper that a student can realistically finish.

Avoid:

- complex data analysis chapters;
- pure theory construction;
- advanced algorithm research;
- large-scale empirical testing;
- unrealistic engineering deployment;
- vague chapter titles such as "相关理论研究" without a concrete function.

## Format

Use numbered headings with no more than three levels:

```text
1 绪论
1.1 研究背景
1.1.1 ……
```

Keep chapter titles concise and action-oriented. The second to fifth chapters should each focus on one main research task. End with conclusion and outlook, references, and acknowledgements when the user asks for a full thesis outline.

## Standard Undergraduate System-Design Outline

Use this pattern for software, platform, website, app, management system, mini-program, game, or information-system topics:

```text
1 绪论
1.1 研究背景
1.2 研究目的及意义
1.3 国内外研究现状
1.4 研究内容与方法
1.5 论文结构安排

2 相关技术与理论基础
2.1 开发技术概述
2.2 系统开发工具与环境
2.3 数据库或数据管理技术
2.4 本章小结

3 系统需求分析
3.1 用户需求分析
3.2 功能需求分析
3.3 非功能需求分析
3.4 可行性分析
3.5 本章小结

4 系统设计
4.1 系统总体架构设计
4.2 功能模块设计
4.3 数据库设计
4.4 关键业务流程设计
4.5 本章小结

5 系统实现与测试
5.1 开发环境搭建
5.2 主要功能实现
5.3 系统测试设计
5.4 测试结果与问题优化
5.5 本章小结

6 总结与展望
7 参考文献
8 致谢
```

Adapt the module names to the exact thesis title. Do not leave generic wording when a concrete topic is available.

## Standard Applied-Research Outline

Use this pattern for management, education, communication, e-commerce, social governance, marketing, or applied humanities/social-science topics:

```text
1 绪论
1.1 研究背景
1.2 研究目的及意义
1.3 国内外研究现状
1.4 研究内容与方法
1.5 创新点与不足

2 相关概念与理论基础
2.1 核心概念界定
2.2 相关理论基础
2.3 分析框架

3 研究对象现状分析
3.1 研究对象概况
3.2 当前发展现状
3.3 主要问题表现

4 问题成因分析
4.1 内部因素分析
4.2 外部因素分析
4.3 关键影响因素归纳

5 优化策略或改进路径
5.1 优化原则
5.2 具体改进措施
5.3 实施保障建议

6 总结与展望
7 参考文献
8 致谢
```

Only include survey, interview, or statistical analysis chapters if the user has data collection conditions.

## Customization Rules

- Map chapter titles to the user's topic, not to a generic template.
- Keep innovation points modest: application scenario, process design, module integration, or localized improvement.
- Ensure every chapter can become a real thesis chapter later.
- If the user provides a school-required chapter list, follow the school list first and adapt these rules inside it.
