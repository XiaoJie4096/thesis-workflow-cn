# 正文大纲模式

按论文类型选一种作为底稿，再按题目和学校要求改名、增删。章名必须写具体对象，不写空泛标题。

## 有模板的类型

下面三类按 `../../../references/paper-types/` 里的模板出大纲。模板给出章节骨架（必有、常见）、子类变体、字数分配和每节的图表：

| 类型 | 判断依据 | 模板 |
|---|---|---|
| 系统设计与实现 | 主要成果是可运行的软件、软硬件系统或平台，按需求、设计、实现、测试展开 | `system-design.md` |
| 算法模型改进 | 在已有算法或模型上做 1–3 处改进，用实验证明有效 | `algorithm-improvement.md` |
| 工程设计 | 主要成果是部件、装置或工程系统的设计方案，核心是设计计算、校核和仿真 | `engineering-design.md` |

先按判断依据确定类型，再在模板的"子类变体"里选和题目最接近的一种，按题目把章名、节名改成具体对象。

## 应用研究 / 方案设计类（管理方案、营销策划）

```text
第1章 绪论
第2章 相关理论与方法
第3章 现状调查与问题分析   表：调查数据；图：问题因果图
第4章 方案/模型设计
第5章 方案实施与效果分析
第6章 结论与建议
```

## 实证研究类（经管、教育、心理、社会学）

```text
第1章 绪论
第2章 文献综述与理论基础
第3章 研究假设与模型       图：理论模型图
第4章 研究设计             表：变量定义表、样本描述表
第5章 实证结果与分析       表：描述统计、相关、回归结果
第6章 研究结论与建议
```


## 人文社科论述类（中文、历史、法学、思政）

```text
第1章 绪论（缘起、综述、方法、创新点）
第2章 <核心概念与理论界定>
第3章 <论点一：现象/文本分析>
第4章 <论点二：成因/比较>
第5章 <论点三：对策/启示>
结语
```

论述类章节按论点推进，每章一个分论点，章名写成观点句或明确对象，图表可少或没有。

## 通用检查

- 绪论的"主要研究内容"要和后面各章一一对应。
- 需求分析里的每个功能，设计和实现章里都要出现；测试章要覆盖核心功能。
- 一章 3–5 节，每节直接写 3–6 段，每段 150–300 字。设计章、实现章一节并列讲几个模块时才分小节。
- 预期图表写在大纲里，后面 `thesis-figures-cn` 按此生成图表清单。
