# 正文大纲模式

按论文类型选 `../../../references/paper-types/` 里的一份模板作为底稿，再按题目和学校要求改名、增删。模板给出章节骨架（必有、常见）、子类变体、字数分配和每节的图表。章名必须写具体对象，不写空泛标题。

| 类型 | 判断依据 | 模板 |
|---|---|---|
| 系统设计与实现 | 主要成果是可运行的软件、软硬件系统或平台，按需求、设计、实现、测试展开 | `system-design.md` |
| 算法模型改进 | 在已有算法或模型上做 1–3 处改进，用实验证明有效 | `algorithm-improvement.md` |
| 工程设计 | 主要成果是部件、装置或工程系统的设计方案，核心是设计计算、校核和仿真 | `engineering-design.md` |
| 实证研究 | 用问卷、企业或区域数据检验变量之间的关系，核心是模型和回归结果（经管、教育、心理、社会学） | `empirical.md` |
| 实验研究 | 通过控制条件的实验比较处理效果，核心是材料方法和测定结果（材料、化学、食品、生物、环境） | `experimental.md` |
| 案例分析对策研究 | 以一个企业、单位或社区为对象，诊断问题并提出优化方案或对策（管理方案、营销策划、公共治理） | `case-study.md` |
| 法学研究 | 围绕一个法律问题，解释规范、分析争点、提出规则完善建议 | `law.md` |
| 人文论述 | 以文本、史料或思想为对象，按分论点推进（文学、历史、哲学、思政） | `humanities.md` |
| 设计创作策划方案 | 主要成果是一套设计作品或教学设计，按调研、策略、设计实践、评价展开（视觉传达、产品、景观、教学设计） | `design-creative.md` |

先按判断依据确定类型。题目兼有两类特征时，按主要结论靠什么证明来选：靠测试和运行选系统设计，靠数据集指标选算法改进，靠回归结果选实证，靠实验测定选实验研究，靠诊断和方案选案例分析。再在模板的变体里选和题目最接近的一种，按题目把章名、节名改成具体对象。

## 通用检查

- 绪论的"主要研究内容"要和后面各章一一对应。
- 前面提出的需求、问题、假设或争点，后面的章节都要逐项回应。
- 一章 3–5 节，每节直接写 3–6 段，每段 150–300 字。一节并列讲几个模块、几项问题或几条对策时才分小节。
- 预期图表写在大纲里，后面 `thesis-figures-cn` 按此生成图表清单。
