# 正文 Markdown 约定

`docx-editor-cn/scripts/md2docx_thesis.js` 按下面的写法把章节 Markdown 转成 Word。写正文时严格按这个格式，转换时才不会丢格式。

## 文件组织

```text
<论文项目>/
├── chapters/
│   ├── 00-摘要.md        # 中文摘要 + 英文 Abstract，可放在一个文件
│   ├── 01-绪论.md
│   ├── 02-相关技术.md
│   ├── ...
│   ├── 07-总结与展望.md
│   ├── 90-参考文献.md
│   └── 91-致谢.md
├── figures/
│   ├── src/              # 图的源文件：*.mmd（Mermaid）、*.py（Python 绘图）
│   └── *.png             # 渲染结果和用户截图
├── plan/                 # 大纲.md、字数分配.json、图表清单.md
├── materials/            # 项目清单.md、项目理解.md、素材缺口清单.md
├── literature/           # 题录摘要.md 等文献记录
└── qc/                   # 质检报告.md
```

文件按文件名排序拼接，所以用两位数字前缀控制顺序。每个文件以一个 `#` 一级标题开头。

## 标题

```markdown
# 第3章 需求分析
## 3.1 可行性分析
### 3.1.1 技术可行性
```

- 标题文字原样输出，脚本不自动编号，所以章节号要自己写全。
- `摘要`、`Abstract`、`参考文献`、`致谢`、`附录…`、`结论`、`总结与展望` 作为一级标题时不计入章号（图表编号不受影响）。如果学校要求"第7章 总结与展望"，就照写，它会正常计章。
- 图表公式编号里的章号取自标题（`第4章`、`第四章`、`4 系统设计` 都能识别），所以只写了部分章节时编号也正确；标题里没有章号时按顺序计数。
- 每个一级标题自动另起一页；目录插在第一个计章的一级标题前面。

## 段落

- 段落之间空一行。同一段可以分多行写，转换时会直接拼接，中文之间不加空格。
- 不要手动输入首行缩进空格，样式里已经有两字符缩进。
- `**加粗**`、`` `代码或英文标识符` `` 可用。不要用斜体和 HTML。

## 引用

- 正文引用写 `[1]`、`[2,3]`、`[4-6]`，转换后为上标。
- 编号按首次出现顺序，必须和 `90-参考文献.md` 一致；只能引用文献库里已有的文献。

参考文献文件：

```markdown
# 参考文献

1. 张三, 李四. 基于Unity3D的休闲游戏设计[J]. 计算机技术与发展, 2021, 31(5): 120-125.
2. ……
```

用有序列表写，脚本会生成 `[1]` 编号和悬挂缩进。

## 图

```markdown
系统整体分为表现层、逻辑层和数据层，如图4-1所示。

![系统总体架构图](../figures/architecture.png){width=14}
```

- 方括号里写图题，不写"图4-1"，编号自动生成在图下方。
- 路径相对于当前 Markdown 文件。`{width=14}` 是宽度（厘米），可省略，默认版心宽度的 85%。
- 图片只支持 PNG/JPG。文件不存在时 Word 里会生成黄色占位框，并在质检报告里列为阻塞项。
- 正文必须先提到"如图4-1所示"再放图。编号规则：第几章 - 本章第几张。

## 表

```markdown
各功能模块的需求如表3-1所示。

表：功能需求表

| 模块 | 功能 | 说明 |
|---|---|---|
| 种植系统 | 播种 | 玩家选择种子后在已翻耕的地块播种 |
```

- `表：标题` 单独一行，紧贴在表格上方，转换后为表上方的"表3-1 功能需求表"。
- 自动生成三线表。单元格里不要换行，内容过长就拆表或改成文字。

## 公式

```markdown
作物生长进度按下式计算：

$$
P = \min\left(1, \frac{t - t_0}{T}\right)
$$

式中，$P$ 为生长进度，$t_0$ 为播种时间，$T$ 为成熟所需时长。
```

- 独立公式用 `$$ … $$`，自动居中并在右侧编号"（4-1）"。
- 行内公式用 `$…$`。

## 代码

用三个反引号的代码块，等宽小字号输出。论文里代码片段每段不超过 20 行，只放核心逻辑，前后要有文字说明。

## 待补充占位

```markdown
本文在【待补充：学院名称】完成。
```

- 只有用户本人才知道的事实（姓名、学校信息、文献缺失的页码）写成 `【待补充：需要什么】`。截图用图片引用加计划文件名，不写占位文字。
- Word 里高亮为黄色，质检报告会列出全部占位，交稿前必须清零。

## 摘要与关键词

```markdown
# 摘要

本文针对……

关键词：Unity3D；农场游戏；模拟经营；C#

# Abstract

This thesis ...

Key words: Unity3D; farm game; simulation; C#
```

`关键词：` 开头的段落会自动加粗标签、取消首行缩进。
